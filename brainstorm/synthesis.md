# Synthesis: Best Practices for Study Notes (6-Source Analysis)

## 1. Universal Consensus (All/Most Sources Agree)

These are the non-negotiables — every source independently arrived at these:

### A. The Core Process: Read First, Write Later
- **All 6 sources** agree: never take notes during the first read
- Preview/skim first to build a schema
- Write notes from memory after reading a section, then check and fill gaps
- Named differently by each source: "4-phase process" (ChatGPT), "SQ3R" (Gemini), "two-stage capture + elaboration" (Claude), "read-massage-test-sharpen" (Perplexity), "skim-read-generate-summarize-test" (Grok)

### B. Retrieval Practice > Passive Reading
- **All 6 sources** agree: notes must contain questions, not just facts
- Self-testing from notes is the single most effective study technique
- "Notes are for making retrieval easier, not storing information" (ChatGPT)
- "If you're not struggling to recall, you're not learning effectively" (ChatGPT)

### C. Subject-Specific Structure
- **All 6 sources** agree: format must adapt to subject type
- Math/Physics: worked examples, formulas, problem types
- Biology/Chemistry: diagrams, flowcharts, processes
- History/Pol Sci: timelines, cause-effect chains, comparisons
- Consensus: use a universal skeleton but vary content type

### D. Common Mistakes Are Universal
- **All 6 sources** identify the same core mistakes:
  1. Verbatim copying
  2. Over-highlighting
  3. Making notes too long/pretty
  4. No questions in notes

### E. Tiering for 8-9 Subjects
- **All 6 sources** agree: you can't go deep on everything
- Prioritize by weightage/difficulty (tiering)
- Use the 80/20 rule — focus effort on high-yield content

## 3. Contradictions / Tensions

### A. "Universal Template" vs "No Universal Template"
- **ChatGPT, Perplexity, Grok**: Use a universal backbone/template
- **Claude**: "There is no universal template. Subject structure should dictate note structure"
- **Resolution**: The consensus is actually a **flexible universal skeleton** (questions, concepts, examples, summary) with **subject-specific content sections**. Claude's point is that the *content structure* must match the knowledge structure, not that there's no shared framework.

### B. How Much to Write
- **ChatGPT**: 1-2 pages per chapter max
- **Perplexity**: Pass 1 = 1-2 pages, Pass 3 = ½ page
- **Grok**: 1-2 pages per chapter max
- **Me**: Detailed notes + 1-page revision sheet (two-layer)
- **Claude**: 3-layer model (core notes → 1-page cues → flashcards)
- **Resolution**: Progressive compression. Start with enough detail to capture understanding, then compress into a 1-page revision sheet for exam use.

### C. When to Write Notes
- **ChatGPT**: Phase 2 = "don't write full notes yet," Phase 3 = retrieval-based writing
- **Perplexity**: First read = annotate lightly, second read = write notes
- **Grok**: Skim first, then read actively and write from memory
- **Claude**: Full read-through without notes, then second pass with notes
- **Gemini**: Scan, read & retrieve, then draft
- **Resolution**: All agree on the same sequence — skim → read → write from memory. The difference is only in naming.

## 4. Proposed SOP Structure

Based on the synthesis, here's the recommended SOP structure:

```
SOP: Creating Effective Study Notes for 8-9 Subjects

1. CORE PRINCIPLES
   1.1 The Golden Rule: Notes Are for Retrieval, Not Storage
   1.2 The 5 Universal Principles (active processing, retrieval practice, dual coding, elaboration, concrete examples)
   1.3 The 4 Common Mistakes to Avoid

2. THE NOTE-TAKING PROCESS (Step-by-Step)
   2.1 Phase 1: Preview & Prime (2-5 min)
   2.2 Phase 2: First Read — Understand, Don't Write (5-10 min)
   2.3 Phase 3: Retrieval-Based Note Creation (10-15 min)
   2.4 Phase 4: Transform into Exam-Ready Notes (5-10 min)
   2.5 Phase 5: Quick Self-Test (5 min)
   Total: 25-45 min per chapter section

3. THE UNIVERSAL SKELETON
   3.1 Cornell Notes Layout (cue column, notes column, summary)
   3.2 What Every Chapter's Notes Must Include
       - Questions/cues
       - Core concepts (compressed)
       - Examples/applications
       - Common mistakes/traps
       - Diagrams/visuals
       - Connections to prior knowledge
       - "So what" summary

4. SUBJECT-SPECIFIC ADAPTATIONS
   4.1 Math & Physics (Procedural)
   4.2 Biology & Chemistry (Declarative + Visual)
   4.3 History & Political Science (Narrative + Causal)
   4.4 Geography (Spatial + Analytical)
   4.5 Economics (Analytical + Applied)
   4.6 English & Hindi (Analytical + Linguistic)
   4.7 Computer Science (Procedural + Conceptual)
   For each: core unit, best format, practice style, common trap, visual encoding

5. MANAGING 8-9 SUBJECTS
   5.1 Tiering System (by weightage + difficulty)
   5.2 One Chapter at a Time Rule
   5.3 Batching Similar Subjects
   5.4 Daily Limits & Time-Boxing
   5.5 Exam Blueprint Pre-Skim

6. QUICK REFERENCE TABLES
   6.1 Subject Variants at a Glance
   6.2 Time Allocation Guide
   6.3 Question Types (Factual / Conceptual / Application)
   6.4 Difficulty Flagging System (✓ / ~ / ✗)
```

## 5. Evidence Base Summary

Key research cited across sources:
- **Dunlosky et al. (2013)** — Retrieval practice = high utility; highlighting/re-reading = low utility
- **Roediger & Karpicke (2006)** — Testing beats re-studying (61% vs 40% retention after 1 week)
- **Fiorella & Mayer (2015)** — Generative processing (rephrasing) is one of the most robust findings
- **Huelser & Metcalfe (2012)** — Errorful generation strengthens correct memory
- **Wammes et al. (2016)** — Drawing effect: hand-drawn diagrams > written descriptions
- **Ausubel** — Advance organizers improve comprehension
- **Ebbinghaus** — Forgetting curve: 50% loss in 1 hour, 70% in 24 hours without reinforcement
- **Bjork** — Desirable difficulties: compression improves long-term retention
